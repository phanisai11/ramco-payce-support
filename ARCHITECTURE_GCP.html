De-duplication

Uses the source ID plus a content hash of (customer, subject, body), with a 24-hour window. The Q3 export has 14 duplicate IDs and repeat customer messages.

Tokenisation (Sensitive Data Protection)

Aadhaar, PAN, bank account, IFSC, IBAN, Emirates ID, phone and email become deterministic tokens such as [PAN:7f3a]. The same value always gets the same token, so the model can reason without seeing the value. Re-identification uses a KMS key held only by the DPO role.

Language

Language detection tags each ticket EN, AR or Hinglish. Q3 has about 107 Arabic and 227 Hinglish texts. The tag drives reply language and glossary use downstream.

Output verifier (every draft, every answer)

  • DLP re-scan on outgoing text. Tokens are re-masked, never expanded into replies.
  • tenant_id of every source equals the ticket's tenant.
  • Every statutory number in the text equals the resolver's value.
  • Citation present: KB ID@version or rule ID + effective date.
  • No commitments ("approved", "refunded", "resubmitted").
  • Model Armor response screen.
  • On failure, block, return "no suggestion" and log the reason.

Human approval points

  • Agent: accept, edit or reject each draft. Only the agent sends.
  • Lead: 2nd reassignment and incident declaration, both logged in-tool.
  • Content owner: publishes KB redlines in Confluence.
  • DPO: re-identification and erasure requests.

Contains tokens, never raw values. Cloud Audit Logs (Data Access) are on for Cloud SQL, BigQuery, DLP, KMS and Vertex AI. Retention is set by the DPO, with an erasure job keyed on the token.

Security, identity & cost controls

  • One service account per service with least privilege. Engine token is read-only and stored in Secret Manager.
  • Tenant is derived server-side from authenticated channel/account mapping, never from browser/payload/model fields. Unknown/conflicting identity is quarantined.
  • Cloud SQL: composite tenant foreign keys + FORCE RLS; runtime roles are not owners/superusers and cannot BYPASSRLS.
  • CMEK via Cloud KMS, VPC-SC and regional Org Policy. IN and UAE tenant objects stay in separate approved cells; no normal cross-cell copy path.
  • Files: public access prevention, uniform bucket access, generation precondition, retention/Bucket Lock; only StorageBroker may issue a short-lived authorized read.
  • Cost governor: token meter per call, daily budget per tenant and for peak week, model tiering (Flash first).
  • Billing budget alerts → Pub/Sub → switch:*. The platform falls back to manual support with no outage.
  • Engine traffic: requests per minute per tenant on a dashboard, with an alert well before 30.

Production economics · extraction-first · no double-billing

Normative rules for prod (full detail in PRODUCTION_DESIGN_GCP.md, gates in EVAL_GATES_GCP.md).

Answer ladder (RAG last)

  • L0–L5: policy block → regex/dictionaries → SQL/Redis → engine API → file validators — 0 LLM.
  • L6: template fill for statutory/status — optional Flash phrase only.
  • L7–L8: trust-ranked RAG + one compose — how-to only, dated chunks.
  • L9: verifier — numbers must match engine; DLP on output.

Idempotent pipeline (reruns ≠ extra cost)

  • content_fingerprint per canonical ticket version + policy/model hash.
  • Stage cache in Cloud SQL / Redis before any embed, LLM, or Document AI call.
  • Pub/Sub handlers idempotent on pipeline_run_id + stage; max 2 retries then human queue.
  • Audit: cache_hit, tokens, cost_usd → BigQuery.

Smart routing

  • 99% auto-route per approved rule/scorer row (G3) — not vector neighbor voting on tickets.
  • Rules → policy tables → optional offline scorer artifact → triage default.
  • decided_by=llm cannot auto-route; export JSON categories not used as labels.
  • ToolBroker: allowlisted read-only tools; status/statutory paths no RAG.
  • Peak auto-lane p95 first reply ≤ 3 s; target ≤10% LLM routing share.

Caches

  • Redis: statutory rates, webhook run state, spend meter, kill switch.
  • Semantic answer cache: non-statutory auto_answer only; cosine ≥ 0.92 (tuned offline); invalidate on rule version.
  • Embed once: keyed on redacted body hash — redelivery does not re-embed.

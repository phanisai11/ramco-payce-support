# SaaS tenant, intake, file, and routing contract

**Status:** Normative build contract. A service that violates this document must not be deployed.  
**Scope:** Ticket/message intake, tenant resolution, raw payloads, attachments, canonical records, retrieval, tools, routing decisions, and audit.
**Machine-readable contracts:** `schemas/raw-intake-event.schema.json`, `schemas/canonical-ticket-event.schema.json`, `schemas/routing-decision.schema.json`.

---

## 1. Non-negotiable invariants

1. **Tenant identity is server-derived.** Never trust `tenant_id`, region, queue, priority, object path, or MIME type supplied in customer content.
2. **Received input is append-only.** The original event and file bytes are never updated. Corrections, new messages, reopens, and reprocessing create new events or derived versions.
3. **Every tenant-owned row and object is tenant-bound.** `tenant_id` is non-null after resolution and is part of database keys, object paths, cache keys, audit records, and authorization checks.
4. **Unresolved identity has no tenant access.** Unknown or conflicting senders remain in an isolated intake quarantine and cannot call tenant-scoped tools or retrieval.
5. **No direct file access.** Customers, agents, models, and general application services never receive bucket credentials or arbitrary `gs://` paths. A storage broker authorizes each read from authenticated server context.
6. **Derived data never replaces evidence.** Canonical text, OCR, redaction, classifications, and drafts point back to immutable raw event/file hashes.
7. **Routing fails closed.** Only a G3-approved rule/policy/scorer row may set `auto_route=true`; ambiguity goes to human triage. No system can honestly guarantee correct automatic routing for every input.
8. **Cross-tenant leakage target is zero.** Any cross-tenant read/write/retrieval result is a release blocker and security incident.

---

## 2. Trust boundary and intake sequence

```text
Authenticated channel adapter
  → create server envelope (event_id, received_at, source identity, trusted ingress region)
  → write raw event/file once to regional quarantine
  → verify hash, size, media type, malware, and DLP
  → resolve tenant from trusted channel/account/contact mapping
      unresolved/conflict → isolated review; no tools/retrieval
      resolved            → bind tenant_id + region immutably
  → create canonical event version
  → extract facts and evaluate policy/routing
  → persist append-only decision + update current-state projection
```

**Tenant resolution order:**

1. Authenticated portal/widget tenant claim verified against the session.
2. Channel-owned mapping (`partner_id`, verified email/contact, WhatsApp account) to one tenant.
3. Explicit manual verification by an authorized support lead.

Display name, email text, attachment contents, model output, or a customer-provided `tenant_id` are never authorization evidence. A mapping conflict creates `tenant_resolution.status = "conflict"` and stops the pipeline after safe scanning.

Each channel endpoint/account is assigned to a trusted ingress region in configuration. An unresolved event stays in that regional quarantine; the payload cannot select or change its storage region.

---

## 3. Storage layout and file isolation

Use **separate regional projects/buckets** for India and UAE. With ~1,400 tenants, a bucket per tenant adds operational and quota burden without replacing authorization. Use a tenant prefix inside each regional bucket, and make the **storage broker** the only reader.

```text
gs://payce-<region>-intake-prod/
  unresolved/<ingress_id>/<event_id>/raw-event.json
  unresolved/<ingress_id>/<event_id>/raw-body
  unresolved/<ingress_id>/<event_id>/files/<attachment_id>

gs://payce-<region>-tenant-raw-prod/
  tenants/<tenant_uuid>/intake/events/<event_id>/raw-event.json
  tenants/<tenant_uuid>/intake/events/<event_id>/raw-body
  tenants/<tenant_uuid>/intake/events/<event_id>/attachments/<attachment_id>/original

gs://payce-<region>-tenant-derived-prod/
  tenants/<tenant_uuid>/tickets/<ticket_id>/events/<event_id>/canonical-v<version>.json
  tenants/<tenant_uuid>/tickets/<ticket_id>/attachments/<attachment_id>/redacted-v<version>
```

**Object rules:**

- Object names are generated by the server from UUIDs; never concatenate user filenames or payload values.
- Preserve the customer filename as escaped metadata only; never use it as a path.
- Create with GCS generation precondition `ifGenerationMatch=0`; a duplicate key fails instead of overwriting.
- Raw buckets use uniform bucket-level access, public-access prevention, versioning, retention policy + Bucket Lock after DPO approval, CMEK, audit logs, and no update/delete permission for runtime service accounts.
- The ingest writer has **create-only** access. Scanner/normalizer can read but cannot overwrite/delete. Derived writer cannot read another tenant through arbitrary paths.
- After manual resolution, promotion from unresolved quarantine is an audited write-once copy to the tenant path using `ifGenerationMatch=0`; destination hash must equal source hash. The quarantine source remains unchanged until its approved retention expiry.
- Store `sha256`, GCS generation, size, detected media type, uploader/source, timestamps, and scan status in the attachment manifest.
- File download uses short-lived brokered URLs or streaming after verifying `(principal, tenant_id, attachment_id, purpose)`. Never accept a caller-provided object URI.
- Region is derived from the verified tenant profile. Moving an object between regions requires an audited migration workflow; normal processing cannot copy it cross-region.
- A dedicated bucket/key may be offered to contractually isolated tenants, but the default regional-prefix model remains secure only with broker authorization and tests.

## 4. Immutable raw envelope

The raw envelope is written before normalization and never edited:

```json
{
  "schema": "com.payce.intake.raw.v1",
  "event_id": "uuid",
  "ingress_id": "uuid",
  "source": "email|widget|partner|whatsapp|phone",
  "source_event_id": "provider-stable-id",
  "received_at": "2026-11-06T08:31:42.123Z",
  "source_occurred_at": "2026-11-06T08:31:39.000Z",
  "authenticated_subject": {
    "principal_id": "server-derived",
    "channel_account_id": "server-derived",
    "ingress_region": "IN"
  },
  "payload_schema": "provider-name/version",
  "raw_body_ref": {
    "object_id": "uuid",
    "sha256": "hex",
    "object_generation": "gcs-generation",
    "size_bytes": 1234
  },
  "payload": {},
  "attachment_receipts": [
    {
      "attachment_id": "uuid",
      "original_filename": "customer-visible-only.pdf",
      "claimed_media_type": "application/pdf",
      "size_bytes": 12345,
      "sha256": "hex",
      "object_generation": "gcs-generation"
    }
  ]
}
```

`raw_body_ref` points to the exact received provider bytes and is the authoritative evidence. `payload` is an immutable parsed convenience copy; it is never treated as byte-faithful evidence or edited in place. Access to both is tightly restricted; downstream services receive only canonical masked events.

## 5. Canonical event contract

Canonical records are immutable **versions**, not mutable replacements:

```json
{
  "schema": "com.payce.ticket.canonical.v1",
  "event_id": "uuid",
  "canonical_version": 1,
  "raw_ref": {
    "object_id": "opaque-storage-broker-id",
    "sha256": "hex",
    "generation": "gcs-generation"
  },
  "ticket": {
    "ticket_id": "PN-101253",
    "case_id": "CASE-8812",
    "tenant_id": "C-1002",
    "region": "IN"
  },
  "tenant_resolution": {
    "status": "resolved",
    "method": "authenticated_session|verified_contact|manual",
    "mapping_version": "2026-11-06"
  },
  "time": {
    "received_at": "RFC3339 UTC",
    "source_occurred_at": "RFC3339 UTC",
    "customer_message_at": "RFC3339 UTC",
    "payroll_period": "2026-08",
    "t_as_of": "2026-08-31T23:59:59Z",
    "payroll_week": true
  },
  "content": {
    "subject_masked": "string",
    "body_masked": "string",
    "language": "en|hi|hi-Latn|ar",
    "content_sha256": "hex"
  },
  "facts": {
    "run_id": null,
    "jira_keys": [],
    "kb_ids": [],
    "error_codes": [],
    "refund_refs": []
  },
  "attachments": [
    {
      "attachment_id": "uuid",
      "manifest_version": 1,
      "detected_media_type": "application/pdf",
      "size_bytes": 12345,
      "sha256": "hex",
      "scan_status": "clean|blocked|pending",
      "pii_class": "none|sensitive|restricted",
      "processing_status": "metadata_only|redacted_ready|human_only"
    }
  ],
  "provenance": {
    "normalizer_version": "string",
    "dlp_policy_version": "string",
    "created_at": "RFC3339 UTC"
  }
}
```

**Validation requirements:**

- JSON Schema rejects unknown required-domain enum values, extra top-level fields, non-UTC timestamps, missing hashes, unresolved tenants on tenant topics, and attachment references whose manifest tenant differs.
- Payload size, message count, attachment count/size, string length, decompression ratio, and archive nesting have hard limits.
- `ticket.tenant_id`, `ticket.region`, `raw_ref`, and hashes cannot change between versions for the same event.
- A customer correction is a new `ticket.message_received` event. A processing fix creates `canonical_version + 1`; it never edits v1.

## 6. Database isolation model

For every tenant-owned table:

- `tenant_id NOT NULL`.
- Primary/unique keys include `tenant_id` where feasible.
- Foreign keys are composite: `(tenant_id, parent_id)` → parent `(tenant_id, id)`. This prevents accidental cross-tenant joins even before RLS.
- Enable and **FORCE ROW LEVEL SECURITY**.
- Policies compare `tenant_id` to `current_setting('app.tenant_id', true)`.
- Request middleware runs `SET LOCAL app.tenant_id = <server-authenticated tenant>` inside a transaction. Never take this value from request JSON.
- Runtime roles are not table owners, superusers, or `BYPASSRLS`. Migrations use a separate role.
- Global reference tables (approved KB/rules) are explicitly marked global/region-scoped; they never contain tenant ticket/file content.

Minimum append-only tables:

```text
raw_event_manifest(tenant_id?, event_id, region, object_id, generation, sha256, received_at)
attachment_manifest(tenant_id?, attachment_id, event_id, object_id, generation, sha256, scan_status)
canonical_ticket_event(tenant_id, event_id, canonical_version, canonical_json, created_at)
routing_decision(tenant_id, decision_id, event_id, canonical_version, input_fingerprint,
                 policy_version, rule_id, queue_id?, auto_route, reason_codes, created_at)
audit_event(tenant_id?, audit_id, event_type, actor, resource_type, resource_id, purpose, created_at)
```

`ticket_current` and `routing_current` may be mutable projections rebuilt from append-only events. They are convenience views, never the evidence record.

Rows where `tenant_id` is still null live in a separate intake-quarantine schema/role; tenant application roles cannot query them. Resolution creates a tenant-bound manifest record that references the unchanged quarantine hash/generation.

## 7. Tenant-safe retrieval, caches, and tools

- Every query takes tenant/region from authenticated server context, not model arguments.
- Tenant-private retrieval predicate is mandatory: `tenant_id = :ctx_tenant_id AND region = :ctx_region`.
- Shared KB retrieval predicate is mandatory: `region = :ctx_region AND valid_from <= :t_as_of AND (valid_to IS NULL OR :t_as_of < valid_to)`.
- A retrieval result with the wrong tenant/region is discarded, audited, and pages Security; it is never passed to the composer.
- Cache keys start with environment + region + tenant, for example `prod:IN:C-1002:run:<run_id>`. Global caches are allowed only for explicitly global, non-tenant data.
- ToolBroker resolves tenant server-side and passes tenant-scoped credentials. Tool calls where the resource tenant does not equal context tenant fail before network access.
- The model cannot provide `tenant_id`, object path, SQL predicate, credentials, or tool scope.

## 8. Routing contract

Routing is deterministic and auditable:

```json
{
  "schema": "com.payce.routing.decision.v1",
  "decision_id": "uuid",
  "tenant_id": "C-1002",
  "event_id": "uuid",
  "canonical_version": 1,
  "input_fingerprint": "sha256",
  "policy_version": "routing-2026-11-06.1",
  "lane": "block|status|file_check|incident|auto_answer|draft_for_agent|human",
  "queue_id": "Statutory-Compliance",
  "auto_route": true,
  "decided_by": "rule|policy_table|routing_scorer|human",
  "rule_id": "route-in-pf-v3",
  "reason_codes": ["REGION_IN", "ENTITY_PF", "RULE_G3_APPROVED"],
  "confidence": 1.0,
  "supersedes_decision_id": null,
  "created_at": "RFC3339 UTC"
}
```

**Rules:**

- `auto_route=true` requires resolved tenant, canonical schema pass, no blocking risk, a non-null `rule_id`/approved scorer row in the G3 manifest, and the exact input fingerprint evaluated in CI-compatible code.
- `decided_by=llm|suggest` can never set `queue_id` automatically.
- P1, money movement, security/privacy, unresolved tenant, conflicting period/region, blocked attachments, and uncertain domain go to human review.
- A later decision supersedes but never edits the earlier one; it stores `supersedes_decision_id`.
- Queue capacity affects assignment **within an approved destination pool**, never changes the ticket domain.

## 9. Release gates

| Gate | Mandatory evidence |
|------|--------------------|
| **Tenant isolation** | Cross-tenant SQL, object, cache, retrieval, and tool probes all denied; zero leaks in tests |
| **Immutable intake** | Duplicate source event is idempotent; overwrite/delete attempts fail; hash/generation replay matches |
| **Payload contract** | JSON Schema and boundary/fuzz tests pass for every channel and attachment manifest |
| **Tenant resolution** | Unknown/conflicting sender cannot reach tenant topics, retrieval, files, or tools |
| **Routing** | G3 ≥99% precision per approved auto-route rule/scorer row; all other cases abstain |
| **File safety** | Malware/DLP/zip-bomb tests; original inaccessible to model; redacted derivative bound to same tenant |
| **RAG** | Region/date filters enforced before ranking; wrong-region and stale chunks return zero results |
| **Audit/replay** | Any decision can be reproduced from raw hash + canonical version + policy/model versions |

Shadow mode must run with `auto_route=false` before per-rule activation. A tenant isolation or immutable-input failure blocks the entire release, regardless of model quality.

---

## 10. Final implementation decision

Build the backend in this order:

1. Tenant registry, authenticated channel mapping, regional storage, storage broker.
2. Immutable raw envelope + attachment manifest + idempotent ingest.
3. Canonical schema/versioning + database composite keys/RLS.
4. PII/malware gates and tenant isolation test suite.
5. Deterministic extraction, policy lanes, and append-only routing decisions.
6. G3-approved rule routing in shadow mode.
7. Engine/status/file validators and incident fingerprints.
8. Region/time-filtered how-to RAG, composer, verifier.
9. UI only after the backend contracts and gates pass.
